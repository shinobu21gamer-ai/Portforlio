1. SYSTEM OVERVIEW
================================================================================

The HRMS is a web-based Human Resource Management System integrated into the
MiniMart POS platform. It manages the complete employee lifecycle from hiring
to payroll, with two distinct user roles that have different permission levels.

SYSTEM ARCHITECTURE:
  Frontend:  React + Vite (Port 3001)
  Backend:   Express.js + Sequelize ORM (Port 5000)
  Database:  SQLite (single file: database.sqlite)
  Auth:      JWT tokens with bcrypt password hashing

WHAT THE SYSTEM DOES:
  - Manages employee records (personal info, department, position, salary)
  - Tracks daily attendance with automatic late/overtime detection
  - Handles shift scheduling (templates + permanent + date-specific assignments)
  - Processes job postings with a multi-stage hiring pipeline
  - Manages employee contracts (probationary, regular, contract-based)
  - Handles leave requests with two-stage approval
  - Computes Philippine payroll (SSS, PhilHealth, Pag-IBIG, BIR tax)
  - Provides admin dashboard with pending approval notifications

KEY DESIGN DECISIONS:
  - Two-role system: Admin (approve-only) and HR (full CRUD)
  - Soft delete on all records (data preserved for audit trail)
  - Automatic status transitions (hire creates employee + contract)
  - Philippine labor law compliance (SSS 2024, PhilHealth 5%, Pag-IBIG 2%)

2. ROLE-BASED ACCESS CONTROL
================================================================================

The system has two roles with distinct permission levels:

+-------------------+-------------------+-------------------+
| MODULE            | ADMIN             | HR                |
+-------------------+-------------------+-------------------+
| Dashboard         | View + Approvals  | View Only         |
| Employees         | View + Approve    | Full CRUD         |
| Departments       | View Only         | Full CRUD         |
| Positions         | View Only         | Full CRUD         |
| Attendance        | View + Export     | Full CRUD + Export |
| Schedules         | View Only         | Full CRUD         |
| Job Postings      | View + Approve    | Full CRUD + Close |
| Applications      | View Only         | Full Pipeline     |
| Interviews        | View Only         | Full CRUD + Result|
| Contracts         | View + Approve    | Full CRUD         |
|                   | + Reject/Terminate|                   |
| Leaves            | View + Approve    | Full CRUD         |
|                   | + Reject          | + HR Review       |
| Payroll           | View + Pay        | Full CRUD + Export|
| Resume Files      | View              | View              |
+-------------------+-------------------+-------------------+

WHAT THIS MEANS:
  Admin = Business owner who reviews and approves HR decisions
          Cannot create, edit, or delete records
          Can approve/reject employees, jobs, contracts, leaves
          Can pay processed payroll
          Can terminate contracts
          Can close job postings

  HR    = Human resources staff who manage day-to-day operations
          Can create, read, update, delete all records
          Cannot approve employees (must go through Admin)
          Cannot pay payroll (must go through Admin)
          Cannot terminate contracts (must go through Admin)
          Handles the full hiring pipeline (interviews, scheduling)
          Generates and processes payroll

DESIGN REASONING:
  This separation ensures checks and balances. HR handles operations
  while Admin retains financial and employment decision authority.
  Prevents a single role from both creating and approving records.

4. CROSS-MODULE INTERACTIONS
================================================================================

These are automatic actions that happen when certain events occur
in the system. They connect multiple modules together.

INTERACTION 1: HIRE AUTO-CREATION
  When: Application status set to "hired"
  What happens:
    1. Employee record created (status = "pending")
    2. Contract record created (type = "probationary")
    3. Job openings decremented by 1
    4. If openings = 0, job status = "filled"
  Why: Eliminates manual data entry, ensures consistency

INTERACTION 2: EMPLOYEE-CONTRACT SALARY SYNC
  When: HR edits employee salary
  What happens:
    1. Active contract salary updated to match
    2. Contract's updatedAt timestamp touched
  Why: Employee salary is the source of truth
  Direction: Employee --> Contract (one-way only)

INTERACTION 3: LEAVE APPROVAL AUTO-ATTENDANCE
  When: Admin approves a leave request
  What happens:
    1. For each day in leave range (weekdays only):
       - Skip if weekend (Saturday/Sunday)
       - Skip if attendance record already exists
       - Create attendance record with status = "on-leave"
  Why: Keeps attendance records accurate for payroll

INTERACTION 4: LEAVE REJECTION CLEANUP
  When: Admin rejects a leave request
  What happens:
    1. For each day in leave range:
       - Remove any "on-leave" attendance records
  Why: Cleans up records if leave was previously approved

INTERACTION 5: CONTRACT TERMINATION CASCADE
  When: Admin terminates a contract
  What happens:
    1. Contract status = "terminated"
    2. Employee status = "inactive"
  Why: Terminated contract means employee is no longer active

INTERACTION 6: INTERVIEW RESULT CASCADE
  When: HR sets interview result (pass/fail)
  What happens:
    If pass + initial interview: application --> "final-interview"
    If pass + final interview: application --> "accepted"
    If fail: application --> "rejected"
  Why: Automates pipeline progression, prevents manual tracking

INTERACTION 7: JOB OPENINGS AUTO-DECREMENT
  When: Application status set to "hired"
  What happens:
    1. Job openings reduced by 1
    2. If openings = 0, job status = "filled"
  Why: Prevents over-hiring for a position

6. PAYROLL COMPUTATION FORMULAS
================================================================================

The system computes Philippine-standard deductions:

SSS CONTRIBUTION (2024 Table):
  Based on monthly salary bracket:
  - P0 - P3,250:        Employee P135,    Employer P225
  - P3,250 - P3,750:    Employee P157.50, Employer P262.50
  - P3,750 - P4,250:    Employee P180,    Employer P300
  - ... (46 brackets)
  - P24,750+:           Employee P1,125,  Employer P1,875

PHILHEALTH CONTRIBUTION:
  Formula: Monthly Salary x 5% = Total Contribution
  Employee Share: Total / 2 (50% split)

PAG-IBIG CONTRIBUTION:
  Formula: Monthly Salary x 2%
  Maximum Employee Contribution: P200

BIR WITHHOLDING TAX (2023 Monthly Tax Table):
  Taxable Income = Gross - SSS - PhilHealth - PagIBIG
  - P0 - P20,833:           P0 tax
  - P20,833 - P33,333:      15% of excess over P20,833
  - P33,333 - P66,667:      P1,875 + 20% of excess over P33,333
  - P66,667 - P100,000:     P8,541.67 + 25% of excess over P66,667
  - P100,000 - P200,000:    P16,875 + 30% of excess over P100,000
  - P200,000 - P500,000:    P46,875 + 32% of excess over P200,000
  - P500,000+:              P142,875 + 35% of excess over P500,000

OVERTIME COMPUTATION:
  Hourly Rate = Monthly Salary / 26 working days / 8 hours
  Overtime Pay = OT Hours x Hourly Rate x 1.25

ABSENT DEDUCTION:
  Absent Deduction = (Absent Days / Total Working Days) x Monthly Salary

GROSS PAY:
  Gross = Basic Salary + Overtime Pay + Bonus

NET PAY:
  Net = Gross - SSS - PhilHealth - PagIBIG - Tax - Absent Deduction
